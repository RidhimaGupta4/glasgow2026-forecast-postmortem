# Glasgow 2026 medal-table forecast: a leakage-free post-mortem

[![tests](https://github.com/RidhimaGupta4/glasgow2026-forecast-postmortem/actions/workflows/ci.yml/badge.svg)](https://github.com/RidhimaGupta4/glasgow2026-forecast-postmortem/actions/workflows/ci.yml)

The Royal Statistical Society's 2026 prediction competition asked entrants to rank all 74 nations in the Glasgow 2026 Commonwealth Games medal table before the Games began. This repository scores forecasts of that table against the final table, the way the competition does. It also asks the question that matters more than the raw score: **did the forecast beat simple baselines that anyone could have built, and where did it go wrong?**

Every input is restricted to what was public before the deadline (23:59 BST, 22 July 2026). The analysis plan was committed before anything was scored.

> **Status:** the baselines are complete. The original competition entry is scored automatically once its CSV is added (see [`data/forecast/README.md`](data/forecast/README.md)).

## Key findings

| | tau | 95% interval | Share of best possible |
|---|---|---|---|
| **Best possible this year** | **0.828** | | 100% |
| B1: Birmingham 2022 table carried forward | 0.588 | [0.468, 0.695] | 71% |
| B1p: 2022, only sports on the 2026 programme | 0.585 | [0.466, 0.690] | 71% |
| B2: population + GDP model | 0.424 | [0.278, 0.558] | 51% |
| B0: competition default (all tied) | 0 | | 0% |

1. **The ceiling is 0.828, not 1.** 464 of the 2,701 pairs of nations finished level (29 nations won nothing), and the rules score every tied pair as zero. Any score should be read against 0.828.
2. **"Last Games carried forward" is a tough benchmark.** It beats the population + GDP model by 0.164 (paired 95% interval [0.043, 0.288]).
3. **Adjusting for the cut-down 10-sport programme did not help.** The difference was −0.003 ([−0.026, 0.020]). It fixed some nations (Singapore) but broke others (India, whose boxers won far more in 2026).
4. **2026 was not unusually hard.** Carry-forward scored 71.1% of the best possible in 2018, 71.4% in 2022 and 71.0% in 2026.
5. **The lost score is almost entirely among smaller nations.** Of the 0.240 that B1 lost against the ceiling, only 0.004 involved the 2022 top ten. One gold moves a small nation 10 to 20 places.

The full write-up, with every number generated by code, is in **[REPORT.md](REPORT.md)**.

## How leakage is ruled out

Details are in [LEAKAGE_AUDIT.md](LEAKAGE_AUDIT.md).

- **Two-stage code.** Forecasts are built from an object that never contains the 2026 results. A test deletes the 2026 file and checks that every forecast is identical.
- **Point-in-time features.** Population and GDP come from CIA World Factbook snapshots pinned by git commit. The 2026 snapshot is dated 17 May 2026, and the code refuses any snapshot after a cut-off.
- **Vintage discipline.** The home-nation GDP split uses the ONS release of April 2025. The September 2026 release is deliberately excluded.
- **No tuning on 2026.** The models have no hyperparameters, and training uses earlier Games only.
- **Pre-registration in git.** Plan, data and code were committed before the first score. Every later change is logged with its reason in [ANALYSIS_PLAN.md](ANALYSIS_PLAN.md), and none changes a score or verdict.
- **The competition's exact metric.** scipy's default tau-b would give 0.713 instead of 0.588 for B1. The metric is tested against a literal transcription of the published formula.
- **Paired uncertainty.** A paired nation bootstrap drops self-pairs. A forecast "beats" another only if the paired 95% interval excludes zero.

## Repository layout

```
data/
  raw/            medal tables 2014-2026 and 2022 by sport (transcribed, totals tested)
  reference/      74 nations, 2026 programme, pinned Factbook commits, ONS shares
  interim/        point-in-time population and GDP (built by scripts/extract_factbook.py)
  forecast/       slot for the original submission + provenance template
src/cgpm/
  data.py         loaders; pre-Games data kept apart from the 2026 result
  ranking.py      medal-table ranking rules
  scoring.py      competition tau, ceiling, pair counts
  baselines.py    B0, B1, B1p, B2
  bootstrap.py    paired nation bootstrap, permutation null
  decompose.py    tiers, biggest misses, programme and host effects
  figures.py, report.py, pipeline.py, submission.py, features.py
tests/            46 tests: metric, bootstrap, data integrity, leakage guards, reproducibility
results/          tables (CSV), figures (PNG), metrics.json
ANALYSIS_PLAN.md  pre-scoring plan + change log
LEAKAGE_AUDIT.md  every leakage and statistical risk, with its control
REPORT.md         generated write-up
DATA_SOURCES.md   sources, checks and licences
```

## Reproduce

```bash
pip install -r requirements.txt   # Python 3.13, pinned versions
make all                          # 46 tests, then the full pipeline (about 5 seconds)
```

A fresh run reproduces the committed tables to 1e-12; CI checks this on every push. `make data` rebuilds the Factbook features from the pinned commits (needs network).

## Adding the original competition entry

```bash
python scripts/validate_submission.py RSS_pred_comp_submission_NAME.csv
cp RSS_pred_comp_submission_NAME.csv data/forecast/original_submission.csv
git add -f data/forecast/original_submission.csv && make all
```

Use the exact file emailed before the deadline, and record the email's timestamp and the file's hash in `data/forecast/PROVENANCE.md`. The report then gains a scored section for the original, with paired comparisons against each baseline.

## Limitations

These are covered in full in REPORT.md, section 7.

- The intervals reflect variation over nations, not the luck of individual finals.
- The programme filter works on whole sports.
- GDP for a few tiny territories is imputed by a fixed rule.
- Medal tables were transcribed from Wikipedia, with totals checked against the published totals.
